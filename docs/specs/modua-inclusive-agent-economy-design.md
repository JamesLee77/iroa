- 문서 상태: 확장 설계 반영·작성 문서 사용자 재검토 대기
- 작성일: 2026-08-14
- 확장 설계 승인일: 2026-08-14
- 프로젝트 성격: HEFI와 별개의 신규 프로젝트
- 공식 브랜드: MODUA(모두아)
- 백서 기준 시장: 대한민국 우선, 검증 후 해외 확장

## 1. 설계 목적

MODUA는 노인과 장애인이 일상에서 겪는 정보 이해, 디지털 이용, 결제 확인, 일정 관리, 도움 요청의 어려움을 AI 에이전트로 줄이는 프로젝트다. 가족, 보호자, 자원봉사자, 접근성 평가자, 복지기관과 지역 파트너가 제공한 도움도 투명하게 확인하고 보상한다.

서비스가 중심이고 보상 수단은 보조 장치다. MODUA는 스테이블코인을 발행·수탁·환전하지 않으며, 자체 기반모델·의료진단 시스템·전용 하드웨어를 직접 개발하지 않는다. 기존 AI, 삼성 헬스, 원화 결제, 병원 표준연계 기술을 조합하여 적은 초기 자본으로 검증 가능한 생활자립 서비스를 만드는 것이 목표다. 외부 스테이블코인 결제는 국내 규제와 이용자 보호 조건을 충족한 신고 사업자가 모든 자산 처리를 담당할 때만 후기 실증 기능으로 검토한다.

### 3.2 브랜드 경험

MODUA는 코인이나 투자 상품보다 생활 지원 서비스로 먼저 인식되어야 한다. 시각·음성 경험은 큰 글자, 높은 명암 대비, 짧은 문장, 반복 확인, 느린 안내 옵션을 기본으로 한다. 로켓·차트·코인 가격과 같은 투기적 이미지는 사용하지 않는다.

`MODUA`라는 명칭은 프로젝트 설계상 확정되었다. 다만 외부 공개와 상표 출원 전에는 KIPRIS와 WIPO를 통한 지정상품·서비스별 전문 상표 조사를 수행한다. 현재 백서에는 토큰 티커와 블록체인 네트워크를 기재하지 않는다. 이는 미완성 항목이 아니라 토큰 발행 결정 전 성급한 투자 기대를 만들지 않기 위한 의도적인 제외다.

## 4. 문제 정의와 시장 기준선

### 4.1 해결하려는 문제

노인과 장애인은 하나의 동질적 집단이 아니다. 시각·청각·지체·발달·인지 특성과 디지털 숙련도, 보호자 관계, 경제 상황이 다르다. MODUA가 해결할 우선 문제는 다음 다섯 가지다.

1. 복잡한 문서와 공공·복지 정보를 이해하기 어렵다.
2. 앱 메뉴, 인증, 결제 화면이 복잡하고 실수를 되돌리기 어렵다.
3. 도움이 필요할 때 누구에게 무엇을 요청해야 하는지 알기 어렵다.
4. 가족·자원봉사자·기관의 실질적인 기여가 기록되거나 인정되지 않는다.
5. 당사자의 데이터가 동의 없이 수집·거래될 수 있다는 불신이 크다.

### 4.2 대한민국 시장 기준선

- 2024년 대한민국 65세 이상 인구는 약 1,012만 명이다.
- 보건복지부 등록통계에서 2024년 말 등록장애인은 263만 1,356명이며 주민등록인구의 5.1%다.
- 이 가운데 60대 62만 1,450명, 70대 57만 8,655명, 80세 이상 46만 1,367명으로, 60세 이상 등록장애인은 166만 1,472명이다.
- 통계청 등록센서스 기준 장애인 인구는 약 261만 명, 장애인이 있는 가구는 약 229만 가구다. 등록장애인 행정통계와 등록센서스는 기준이 다르므로 같은 수치처럼 혼용하지 않는다.

노인 인구와 장애인 인구에는 큰 중복이 있으므로 단순 합산하지 않는다. 초기 서비스 가능시장(SAM)은 명확하게 식별 가능한 `60세 이상 등록장애인 약 166.1만 명과 그 지원자·기관`으로 정의한다. 이는 전체 고령자 또는 모든 장애인의 수요를 부정하는 것이 아니라, 초기 사업 검증을 위한 보수적 기준이다.

3년 도달 시나리오는 SAM 기준으로 다음과 같이 둔다.

| 시나리오 | SAM 도달률 | 직접 이용자 |
|---|---:|---:|
| 보수적 | 1% | 약 1.7만 명 |
| 기준 | 3% | 약 5.0만 명 |
| 확장 | 5% | 약 8.3만 명 |

이는 매출 예측이나 가입자 약속이 아니라 사업 규모를 검토하기 위한 시나리오다.

## 5. 이용자와 참여자 역할

| 역할 | 주된 필요 | MODUA가 제공하는 가치 |
|---|---|---|
| 노인·장애인 이용자 | 쉬운 설명, 안전한 확인, 도움 요청, 자기결정권 | 음성·문서·일정·결제 지원과 보상 |
| 가족·보호자 | 필요한 범위의 상태 확인과 지원 | 이용자 동의 기반 알림·연결 |
| 자원봉사자·도움 제공자 | 기여 확인, 활동 이력, 정당한 인정 | 상호 확인된 기여 기록과 포인트 |
| 접근성 평가자 | 제품 개선 참여와 보상 | 구조화된 평가 과제와 결과 확인 |
| 복지기관·지자체 | 이용자 지원, 운영 투명성, 성과 확인 | 기관 포털, 활동 증빙, 집계 보고 |
| 지역·CSR 파트너 | 사회적 기여와 명확한 사용처 | 보상 재원 후원과 성과 보고 |

당사자와 보호자의 권한은 별개다. 보호자라는 이유만으로 대화·결제·건강 관련 정보를 자동 열람할 수 없다. 이용자가 항목별로 범위와 기간을 정하고 언제든 철회할 수 있어야 한다.

## 6. 핵심 제품: AI 생활자립 에이전트

### 6.1 MVP 기능

1. **음성 대화**: 말로 질문하고 쉬운 말로 답변하며, 속도와 반복 횟수를 조절한다.
2. **문서 이해**: 공공 안내문·고지서·복지 문서를 촬영하거나 불러오면 핵심 내용, 기한, 해야 할 일을 설명한다.
3. **일정·복약 알림**: 사용자가 등록한 일정과 복약 시간을 알려준다. 의학적 판단이나 처방 변경은 하지 않는다.
4. **복지 안내**: 검증된 공공·기관 자료를 검색하여 신청 조건과 다음 행동을 설명한다.
5. **도움 요청**: 가족·자원봉사자·기관에 사용자가 선택한 내용만 전달한다.
6. **결제 지원**: 금액·수취인·정기결제 여부를 다시 읽어주고 위험 신호를 알려준 뒤 사용자가 직접 승인하도록 한다.
7. **워치 동반 기능**: 걸음·수면·심박 요약, 진동·음성 알림, 도움 요청과 결제 의도 확인을 제공한다.
8. **병원 방문 지원**: 예약·방문 준비, 사용자 승인 건강·복약 요약, 의료진에게 질문할 내용 정리를 제공한다.

### 6.2 명시적으로 하지 않는 일

- 의료 진단, 처방, 응급상황 판정
- 사용자 확인 없는 송금·구매·계약 체결
- 워치 음성이나 단일 탭만으로 고액·신규 수취인 결제 완료
- 법률·세무·투자 결과의 보장
- 보호자나 기관의 포괄적 감시
- 필수 서비스 이용을 데이터 제공 또는 토큰 보유와 연동

### 6.3 에이전트 권한과 동작 구조

에이전트 권한은 세 단계로 제한한다.

1. **설명**: 문서 읽기, 쉬운 말 변환, 일정·복약 알림은 즉시 수행할 수 있다.
2. **준비**: 예약정보 입력, 도움 요청 작성, 결제 화면 준비는 초안까지만 수행한다.
3. **최종 실행**: 예약 확정, 의료정보 전송, 결제·송금은 사용자의 명시적 재확인과 기존 인증수단을 통과해야 한다.

전체 흐름은 `음성·사진·텍스트·워치 입력 → 접근성·동의 정책 확인 → 의도 파악 → 검증된 정보 검색 또는 허용된 도구 호출 → 쉬운 말 설명 → 위험도 확인 → 초안 준비 → 사용자 최종 승인 또는 사람 연결 → 최소 활동 기록`이다.

도구 호출은 문서 검색, 일정, 연락, 병원 안내, 결제 준비처럼 권한이 분리된 단위로 구성한다. 모델은 도구를 직접 무제한 실행할 수 없으며, 결제·개인정보 공유·외부 연락은 정책 엔진과 명시적 확인을 통과해야 한다.

## 7. 저비용 AI 기술 전략

### 7.1 활용 기술

- 상용 또는 검증된 오픈소스 LLM
- STT/TTS를 이용한 음성 인터페이스
- OCR과 멀티모달 모델을 이용한 문서 이해
- RAG를 이용한 복지·공공정보 근거 검색
- 도구 사용형 에이전트와 정책 기반 실행 제어
- 필요시 소형 온디바이스 모델을 이용한 민감정보 처리와 기본 분류

모델 공급자는 교체할 수 있도록 추상화하고, 한 공급자만 전제하지 않는다. 초기 경쟁력은 대규모 모델 학습이 아니라 접근성 UX, 신뢰 가능한 지식, 안전한 확인 절차, 지역 기관 연계에서 만든다.

### 7.2 당사자 데이터와 에이전트 개선

초기에는 노인·장애인 데이터를 이용한 모델 사전학습이나 파인튜닝을 목표로 하지 않는다. 상용·오픈소스 LLM과 RAG로 시작하고, 동의받은 사용성 평가, 오류 유형, 선호 인터페이스, 과업 성공 여부를 이용해 프롬프트·검색·UI와 안전정책을 개선한다.

동의는 다음 네 갈래로 분리한다.

| 동의 | 성격 | 주요 데이터 | 원칙 |
|---|---|---|---|
| 서비스 운영 | 필수 최소 범위 | 계정, 동의 이력, 요청 상태 | 서비스 제공·보안·분쟁 처리에만 사용 |
| 개인화 기억 | 선택 | 선호 말투, 반복 일정, 접근성 설정 | 이용자가 켜고 끄며 언제든 삭제 |
| 에이전트 개선 | 별도 선택 | 가명화된 평가, 성공·실패 표시 | 거부해도 서비스·보상에 불이익 없음 |
| 의료·임상 연구 | 별도 절차 | 승인된 건강·웨어러블 연구데이터 | 연구설명, 별도 동의, 필요한 기관심의 적용 |

원본 음성·영상·연속 생체신호는 기본적으로 저장하지 않는다. 필요할 때도 개인 암호화 저장소나 기기 안을 우선하며, 연구 영역에는 별도 동의된 가명·최소 데이터만 이동한다. 철회, 삭제, 학습 제외 요청을 제공하고 데이터 자체를 매매하지 않는다. 연구 참여 보상은 데이터 구매대금이 아니라 참여 시간과 검증된 평가 기여에 대한 보상으로 설명한다. 건강데이터 제공량과 포인트를 직접 비례시키지 않는다.

### 7.3 웨어러블

웨어러블은 6~9개월 단계의 선택 기능이다. MVP는 휴대전화의 Samsung Health Data SDK를 통해 사용자가 승인한 걸음·수면·심박 등 집계정보를 가져온다. 원시 ECG·PPG와 연속 센서 처리는 병원 공동연구와 별도 동의·심의·기술검증이 있는 후기 단계에서만 Samsung Health Sensor SDK로 검토한다.

워치는 수집·알림·도움 요청·결제 의도 표시 단말이며, 의료진단이나 자산 보관 단말이 아니다. 워치 미착용, 배터리 부족, 동기화 실패 시 값을 추정하지 않고 `데이터 없음`과 원인을 표시한다. MODUA는 웨어러블 데이터를 질병의 진단·치료 결과로 표현하지 않는다.

### 8.2 핵심 데이터·행동 흐름

- **생활지원**: 이용자 입력 → 동의·정책 검사 → AI 설명 또는 초안 → 이용자 확인 → 허용된 도구 실행 → 최소 감사기록
- **워치 건강정보**: 워치 → Samsung Health → 휴대전화의 승인된 집계정보 → 개인영역 → 필요한 요약만 서비스·병원 연계
- **병원 공유**: 개인영역 → 항목·목적·기간 확인 → 사용자 승인 요약 → 의료진 읽기 전용 확인 → 공유 이력
- **원화 결제**: 워치 또는 모바일 의도 → 수취인·금액·수수료 설명 → 모바일 재확인 → 기존 결제수단 인증 → 결과 확인
- **스테이블코인 결제**: 워치 의도 표시 → 모바일에서 자산·네트워크·수수료·원화환산 재확인 → 신고 사업자의 KYC·AML·수탁·환전 → 가맹점 원화 정산 → MODUA에는 최소 영수증 상태만 기록

### 8.3 보관 영역

| 영역 | 데이터 | 기본 보관 위치 | 사용 목적 |
|---|---|---|---|
| 개인 영역 | 원본 음성·영상, 상세 문서, 민감 건강정보 | 기기 또는 개인 암호화 저장소 | 사용자 기능 제공 |
| 서비스 영역 | 계정, 동의, 최소 활동 기록 | MODUA 서비스 | 운영·보안·분쟁 처리 |
| 연구 영역 | 별도 동의된 가명 데이터와 평가 결과 | 논리적·권한상 분리 저장 | 접근성·에이전트 개선 연구 |
| 보상 영역 | 포인트와 상호확인 증빙 | 별도 보상 원장 | 기여 확인·정산·분쟁 처리 |
| 병원 교환 영역 | 승인된 요약·FHIR 리소스·공유 이력 | 병원 계약과 목적에 따른 분리 환경 | 의료진 읽기와 연계 감사 |

건강·대화·병원 데이터는 블록체인이나 결제 원장에 기록하지 않는다. 각 데이터는 목적, 접근자, 보유기간, 삭제 방법이 표시되어야 한다. 자동화된 추천이나 판단이 이용자의 권리·의무에 중대한 영향을 미칠 수 있는 경우 이유 설명, 사람의 재검토, 이의제기 경로를 제공한다.

### 8.4 병원 연계 단계

1. **생활 연계**: 예약, 이동, 준비물, 진료 질문과 결과를 쉬운 말로 설명한다. 병원 시스템에 접속하지 않는다.
2. **동의된 요약**: 사용자가 선택한 복약·생활·워치 요약을 화면 또는 PDF로 의료진에게 보여준다. 의료진 포털은 읽기 전용이다.
3. **표준 연계**: 병원 계약, 보안검토, 환자 동의가 완료된 경우 KR Core V2/FHIR R4 기반 읽기 연계를 적용한다. EMR 자동 쓰기는 별도 의료기관 승인과 위험평가 전에는 하지 않는다.

진료기록 전송은 환자 또는 적법한 대리인의 범위가 명확한 동의를 전제로 한다. 원시 연속 센서 스트림보다 일일 요약과 예외 이벤트를 우선한다. AI가 진단·처방·응급판정을 하거나 의료진의 결정을 자동 대체하지 않는다.

## 9. 도움과 기여의 확인·보상

### 9.1 보상 가능한 기여

- 노인·장애인의 서비스 사용과 검증된 생활 과업 완료
- 자원봉사자의 이동·문서·디지털 이용 지원
- 가족·보호자의 동의된 지원 활동
- 접근성 테스트와 오류 보고
- 기관의 교육·현장지원·증빙
- 선택 연구 프로그램의 동의된 평가 참여

### 9.2 상호 확인 방식

일반 도움은 `도움을 받은 사람 + 도움을 제공한 사람`의 상호 확인을 기본으로 한다. 금전·민감정보·고위험 활동은 기관 확인 또는 시스템 증빙을 추가한다. 이용자가 직접 확인하기 어려운 경우 사전에 지정된 대리 절차를 사용하되, 한 명이 도움 제공과 최종 승인을 독점하지 못하게 한다.

### 9.3 부정 방지와 분쟁 처리

- 동일 당사자·기기·기관의 반복 패턴과 비정상 빈도를 탐지한다.
- 고위험 보상은 즉시 확정하지 않고 검토기간을 둔다.
- 보상 산정 근거를 이용자에게 쉬운 말로 보여준다.
- 이의신청 시 사람이 기록을 재검토한다.
- 부정 의심만으로 필수 생활지원 기능을 차단하지 않는다.

자원봉사 활동과 고용·유상 노무를 구분한다. 보상이 임금이나 용역대가로 해석될 수 있는 활동은 노무·세무 검토 후 별도 계약 체계로 운영한다.

## 10. 안전한 결제 지원

MODUA는 결제수단이나 스테이블코인을 발행하지 않으며 이용자 자산, 개인키, 환전재원을 보관하지 않는다. 초기에는 기존 카드, 은행계좌, Samsung Wallet 등 원화 결제의 접근성 보조 계층으로 동작한다. 외부 스테이블코인 결제는 16~21개월 단계에서 규제·계약·보안 조건을 통과한 경우에만 제한 실증한다.

결제 전에는 다음 정보를 큰 글자와 음성으로 반복 제시한다.

1. 누구에게 지급하는지
2. 정확한 금액과 수수료
3. 일회성인지 정기결제인지
4. 취소·환불 가능 여부
5. 피싱·사기 또는 평소와 다른 패턴의 위험 신호

최종 실행은 사용자가 기존 결제수단이나 신고 사업자의 화면에서 직접 승인한다. 음성만으로 고액 결제를 완료하거나 에이전트가 사용자를 대신해 자율 결제하지 않는다. 위험도가 높은 경우 가족이 아니라 사용자가 사전에 선택한 신뢰 연락처 또는 기관 상담으로 연결한다.

### 10.1 삼성 워치 결제 역할

Samsung Wallet의 Galaxy Watch 결제는 등록된 호환 결제카드 사용을 기본으로 한다. MODUA는 Samsung Wallet이 스테이블코인 서명·전송을 공식 지원한다고 가정하지 않는다.

워치에서는 금액, 수취인, 결제 자산, 네트워크, 예상 수수료, 원화 환산액과 처리상태만 표시한다. 원화 결제는 기존 Samsung Wallet·카드 인증으로, 스테이블코인은 휴대전화의 제휴 사업자 화면에서 큰 글씨·음성 재확인과 본인 인증 후 완료한다. 워치에 가상자산 개인키를 저장하지 않는다.

### 10.2 조건부 스테이블코인 결제

조건부 실증은 다음을 모두 충족해야 한다.

- MODUA가 발행하지 않은 외부 스테이블코인만 사용한다.
- 국내 이용자 대상 업무를 적법하게 수행하는 FIU 신고 사업자와 계약한다.
- 제휴 사업자가 KYC·AML, 수탁, 전송, 교환, 가맹점 원화정산을 담당한다.
- MODUA는 접근성 설명, 결제 의도 전달, 상태 확인, 고객지원 연결만 담당한다.
- 소액·저빈도·폐쇄형 이용자부터 시작하고 신규 수취인과 고위험 거래에 추가 확인을 적용한다.
- 오송금, 네트워크 선택 오류, 수수료 급등, 피싱, 환불과 분쟁 절차를 출시 전에 검증한다.

신고 사업자 계약, 독립 법률검토, 보안시험 중 하나라도 충족하지 못하면 스테이블코인 결제를 출시하지 않고 원화 결제와 MODUA 포인트만 유지한다.

### 10.3 결제 상태와 중복 방지

각 결제 요청에는 중복 실행을 막는 고유 식별자를 사용한다. 파트너 응답이 없으면 `완료`로 추정하지 않고 `확인 중`으로 표시하며 자동 재결제하지 않는다. 완료·실패·취소·환불 상태는 원 결제사업자의 결과와 일치해야 하고, 이용자가 쉬운 말로 상태와 다음 행동을 확인할 수 있어야 한다.

### 11.2 조건부 총발행량과 배분

조건부 토큰의 최대 발행량은 100억 개이며 추가 발행은 허용하지 않는다.

|---|---:|---:|

지역사회 관련 배분은 총 65%다. 이용자·자원봉사자 및 접근성·데이터 보상 물량은 최소 10년에 걸쳐 배분한다. 팀·자문 물량은 1년 락업 후 4년 선형 베스팅, 사업개발·투자 물량은 1년 락업 후 3년 선형 베스팅을 적용한다. 재단 준비금은 다중서명 지갑과 분기별 사용 내역 공개를 원칙으로 한다.

100억 개 공급은 토큰 가격을 낮게 보장하기 위한 수단이 아니다. 미세 보상 단위와 장기 참여자 수를 고려한 회계 단위다. 백서에는 수익, 가격 상승, 원화 연동, 환매 또는 가치 보장을 표현하지 않는다.

6. 기관용 활동·접근성 관리와 비식별 집계 보고
7. 이용자 동의 기반의 선택적 가족 편의 기능

개인 데이터 판매, 의료 광고, 토큰 가격 상승, 무인가 가상자산 교환 수수료는 수익모델에 포함하지 않는다.

검증 규모는 0~2개월 공동설계 약 20명, 3~5개월 모바일 MVP 30~50명, 6~9개월 워치 통합시험 100~200명으로 단계적으로 늘린다. 10~15개월에는 한 곳의 병원과 읽기 전용 실증을 우선하고, 22~24개월 평가에서 효과·운영비·안전성이 확인된 후에만 다기관·500명 이상 확장을 결정한다.

## 13. 거버넌스

- 이용자 자문위원회는 노인·장애인 당사자가 과반을 차지한다.
- 데이터·윤리위원회는 연구 동의, 고위험 기능, 데이터 사용 변경을 검토한다.
- 재단 자금은 다중서명으로 집행하고 분기별로 공개한다.
- 보상 기준 변경, 대규모 데이터 이용 변경, 토큰 전환 결정은 사전 공지와 이해하기 쉬운 설명을 제공한다.
- 중대한 사고, 보상 분쟁, 모델 성능의 집단별 격차를 정기적으로 공개한다.

거버넌스 투표권을 토큰 보유량만으로 결정하지 않는다. 당사자의 안전과 기본권에 관한 결정은 이용자 대표기구와 독립적인 윤리·법률 검토를 우선한다.

## 14. 단계별 로드맵

초기 핵심팀은 제품·접근성, Android/Wear OS, AI·백엔드, 디자인·QA를 중심으로 4~6명으로 구성한다. 보안, 의료, 개인정보, 금융 법률은 단계별 외부 자문과 파트너 역량을 활용한다. 상용 LLM API, Samsung Health SDK, 관리형 클라우드와 기존 결제망을 우선 사용하고 자체 기반모델·블록체인·스테이블코인·전용 하드웨어를 만들지 않는다.

### 0~2개월: 검증과 협력 준비

- 노인·장애인·지원자 20명 안팎의 유급 공동설계
- 핵심 생활과제 5개와 확장 평가과제 20개 정의
- Samsung Health Data SDK 접근과 워치·휴대전화 동기화 기술시험
- 병원·복지기관·신고 결제사업자 협력 가능성 확인
- 개인정보·연구동의·의료·결제·보상 법률 예비검토

통과 조건은 핵심 과제 확정, 워치 데이터 접근시험 성공, 1개 이상의 병원 또는 지역기관 협력 의향 확보다.

### 3~5개월: 모바일 MVP

- 음성 대화, 문서 설명, 일정·복약 알림, 도움 요청과 지원자 연결
- 원화 결제 설명·확인과 비양도 MODUA 포인트
- 30~50명 폐쇄형 사용성 검증
- 동의 이해·철회, 모델 오류, 접근성 격차와 사기 대응 평가

통과 조건은 핵심 과제의 반복 수행 가능, 중대한 개인정보·결제 사고 0건, 사용자의 동의 이해·철회 가능성 확인이다.

### 6~9개월: Galaxy Watch 동반자

- 걸음·수면·심박 집계정보, 진동·음성 알림, 도움 요청
- 결제 금액·수취인·상태 표시와 휴대전화 최종확인 연결
- 100~200명 규모의 워치·모바일 통합 시험
- 미착용, 배터리 부족, 오프라인과 동기화 실패 대응

통과 조건은 배터리·연결 장애에도 안전한 상태 표시, 잘못된 긴급 알림의 관리 가능성, 미착용 데이터를 정상값으로 오인하지 않는 것이다.

### 10~15개월: 한 곳의 병원과 읽기 전용 실증

- 사용자 승인 복약·생활·워치 요약과 의료진 포털
- 화면·PDF 우선 제공 후 KR Core V2/FHIR R4 읽기 연계
- 병원 계약, 보안검토, 진료기록 전송동의, 필요한 연구심의 적용
- 데이터 출처·측정시각·한계를 의료진이 확인할 수 있게 표시

통과 조건은 병원 계약과 보안검토 완료, 의료진의 출처·한계 확인, 진단·처방 자동화가 없는 것이다.

### 16~21개월: 조건부 스테이블코인 결제 실증

- FIU 신고 사업자가 KYC·AML·수탁·환전·원화정산 담당
- 워치는 결제 의도 표시, 휴대전화는 큰 글씨·음성 재확인과 최종 인증
- 소액·저빈도·폐쇄형 이용자부터 실증
- 오송금·사기·수수료·중복결제·취소·환불 시험

통과 조건은 신고 사업자 계약, 독립 법률검토, 보안시험, 고객지원·분쟁절차 완료다. 하나라도 충족하지 못하면 이 단계를 연기하거나 제외한다.

### 22~24개월: 확장 여부 결정

- 병원·복지기관 추가와 지역 확대 가능성 검토
- 운영비, 생활문제 개선, 의료진·지원자 업무부담 평가
- 외부 보안·개인정보·접근성 점검
- 포인트 장기구조와 100억 개 조건부 토큰의 필요성 독립 검토

확대 조건은 이용자 생활문제 개선, 파트너 운영부담의 수용 가능성, 지속 가능한 계약·후원 재원 확보다. 토큰 발행은 24개월 로드맵의 확정 결과가 아니라 이후 별도 승인 대상이다.

## 15. 품질·안전·평가 기준

### 15.1 출시 기준

- 우선 생활 과업 20개의 과업 완료율 80% 이상
- 의료정보 공유와 결제 관련 외부 행동의 명시적 사용자 승인율 100%
- 해결되지 않은 중대 개인정보·결제 사고 0건
- 위험한 답변과 근거 없는 안내에 대한 사람 연결 경로 100% 제공
- 워치 미착용·오프라인·동기화 실패를 정상 건강값으로 표시한 사례 0건
- 결제 재시도와 네트워크 지연으로 인한 중복 실행 0건

### 15.2 필수 평가

- 장애 유형, 연령, 성별, 음성 특성, 디지털 숙련도별 과업 성공률 격차
- STT 인식 오류와 반복·수정 성공률
- 문서 요약의 금액·날짜·수취인 정확도
- 복지정보 답변의 출처 제시율과 최신성
- 피싱·사기·강압 결제 시나리오 대응
- 보호자 권한 오남용과 개인정보 과다공유 방지
- 보상 중복·담합·대리 확인 탐지
- 연구동의 철회와 데이터 삭제의 실제 처리 검증
- 연구 참여 거부가 서비스·보상에 불이익을 주지 않는지 검증

의학적·법률적·재정적 고위험 답변은 일반 대화 품질과 별도로 평가한다. 평균 성능만으로 출시하지 않고, 주요 이용자 집단 중 하나라도 안전 기준을 충족하지 못하면 해당 기능을 제한한다.

### 15.3 핵심 운영지표

- 노인·장애인 집단별 핵심 생활과제 완료율과 도움 요청률
- 동의 내용 이해율, 선택 변경률, 철회·삭제 처리시간
- 중대한 개인정보·의료·결제 사고 수와 해결시간
- 지원 요청 접수·응답·완료시간과 분쟁률
- 병원 실증에서 의료진의 정보 확인시간과 중복 업무 감소
- 이용자·지원자·기관 한 곳당 월 운영비와 파트너 유지율

토큰 가격, 거래량, 데이터 수집량은 생활자립 성과를 대체하는 핵심지표로 사용하지 않는다.

## 18. HEFI 참고자료 사용 원칙

기존 HEFI 한국어·영어 백서는 구조와 서비스 아이디어를 검토하기 위한 참고자료일 뿐이며, 구현·계약·의료효과·사업성과의 증거로 사용하지 않는다.

MODUA가 새 설계로 재검토하여 활용할 수 있는 아이디어는 다음과 같다.

- 음성 동반자, 복약·운동 알림, 가족·지원자 연결
- 교통·생활서비스 탐색과 예약 준비
- 웨어러블 활동 요약과 사용자가 선택한 건강관리 지원
- 병원 방문 준비와 동의된 요약 공유
- 결제 금액·수취인·수수료를 쉬운 말로 설명하는 접근성 경험

다음 HEFI 요소는 MODUA가 상속하지 않는다.

- HEFI 명칭, 로고, 토큰명과 계약 주소
- 기존 발행량, 배분표, 체인 또는 기술 사양
- 기존 사업 파트너, 재무 전망, 로드맵과 성과 주장
- 검증되지 않은 의료·헬스케어 효능 또는 투자 표현
- 건강데이터 판매·타깃 마케팅·데이터 제공량 연동 보상
- AI Care NFT, Grade NFT, 토큰 보유량 중심 등급·거버넌스
- 자체 사이드체인·IPFS·서버 보관형 이용자 개인키를 기본으로 하는 구조
- 진단·응급판정·의료행위 또는 자율 금융행동을 AI가 대체한다는 주장

HEFI 문서 간에 확인된 ERC-20/BEP-20 및 10억/30억 발행량의 불일치도 MODUA 백서로 옮기지 않는다. MODUA의 모든 수치와 주장은 새 조사 자료와 승인된 설계에서 다시 출발한다.
