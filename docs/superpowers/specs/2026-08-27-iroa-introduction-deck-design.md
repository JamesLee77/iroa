# IROA.AI 소개 프레젠테이션 설계

## 목적

외부 파트너·기관·투자자가 IROA.AI를 또 하나의 앱이나 단순 챗봇이 아니라, 노인과 장애인의 생활 요청을 여러 이용 창구와 안전한 실행 공간, 사람 도움으로 끝까지 이어주는 생활 지원망으로 이해하게 한다. 발표 후에는 초기 현장 검증과 파트너십 대화를 시작할 수 있어야 한다.

## 청중과 사용 상황

- 주요 청중: 지자체·복지기관·병원·상점 및 프랜차이즈·사회공헌 파트너·초기 투자자
- 사용 상황: 10–15분 소개 발표, 첫 미팅, 제휴 검토, 초기 사업 설명
- 언어: 한국어
- 분량: 16:9, 14장
- 산출물: 편집 가능한 PPTX 1개

## 핵심 메시지

**한 번 말한 요청이 어디서든 이어지고, 사용자가 통제하며, 실제 결과까지 도달한다.**

## 내러티브

문제와 사용자의 부담을 먼저 보여주고, 하나의 요청이 이어지는 경험으로 IROA의 차이를 설명한다. 이어 제품 체계와 안전한 실행 원칙, 사람 도움, 사업·로드맵을 증명한 뒤 구체적인 현장 협력 제안으로 닫는다.

## 슬라이드 구성

1. **표지 — 일상을 이롭게. 필요한 일을 끝까지.**
   IROA.AI 공식 워드마크와 사람 관계 중심 Pexels 사진. 부제는 “노인과 장애인의 생활 요청을 끝까지 돕는 AI 지원망”.
2. **디지털 서비스가 늘수록 어떤 사람의 일상은 더 복잡해집니다**
   앱 설치·인증·작은 화면·복잡한 절차가 예약·이동·결제·복지 접근을 끊는다는 문제를 한 문장과 네 가지 생활 요청으로 제시.
3. **IROA는 한 번 말한 요청을 어디서든 이어갑니다**
   전화 → 워치 → 보안 실행 공간 → 키오스크·사람 도움으로 이어지는 하나의 요청. “기기를 배우는 대신 원하는 결과를 말하고 선택하고 승인한다.”
4. **병원 예약부터 이동 준비까지 하나의 요청으로 연결합니다**
   재활병원 예약·휠체어 이동·전날 알림·예외 인계 사례.
5. **현장에서는 메뉴 탐색보다 주문 완료가 중요합니다**
   키오스크가 접근성 설정과 조건을 이해하고 결제 전 최종 확인 및 직원 인계를 수행하는 사례.
6. **하나의 요청 상태를 일곱 개 이용 창구가 공유합니다**
   AI 도우미, Mobile, Watch, 보안 실행 공간, Kiosk, Companion, 지원망을 하나의 중심 요청 주위에 배치.
7. **자동으로 움직이되, 사용자를 대신 결정하지 않습니다**
   요청 → 계획 → 선택 → 승인 → 실행 → 검증 → 복구·사람 인계의 생명주기. 결제·계약·민감정보 전송은 별도 확인.
8. **기기를 꺼도 오래 걸리는 요청은 안전하게 계속됩니다**
   요청별 격리, 일회성 권한, 공식 연결 우선, 결과·삭제 확인을 보안 실행 공간의 역할로 설명.
9. **기술이 막히면 사람이 자연스럽게 이어받습니다**
   가족·활동지원사·기관 직원·상점 직원·지역사회 도움을 선택 가능한 경로로 제시. 반려기기는 사람 관계를 대체하지 않음.
10. **개인정보를 모으기보다 필요한 권한만 연결합니다**
    최소 정보, 필요한 시간, 필요한 실행 공간, 취소·삭제·복구 권리를 네 원칙으로 설명.
11. **기관과 상점은 접근성을 비용이 아니라 운영 성과로 바꿀 수 있습니다**
    사용자, 기관, 상점, 도움 제공자, 실행 공간 운영자의 상호 가치를 평면 구조로 제시.
12. **수익은 기관 계약·상점 구독·공공지원·실행 기여 보상을 조합합니다**
    생활 서비스 이용을 토큰 보유와 연결하지 않으며 원화·기존 결제수단을 기본으로 둔다는 경계를 포함.
13. **작게 검증하고 안전 기준을 통과하며 확장합니다**
    0–3개월 생활 요청·반려 친구 → 4–6개월 보안 실행 공간 → 7–10개월 키오스크 → 11–20개월 기관·병원 연계 → 21개월 이후 안전한 로봇 확장.
14. **첫 현장은 함께 만들 수 있습니다**
    복지기관의 예약·이동, 소규모 매장의 실행형 키오스크, 병원의 방문 준비 중 하나를 공동 검증하자는 명확한 협력 제안. `iroa.ai` 표기.

## 시각 시스템

- 시각 경로: 사용자 지정 공식 Track A BI를 적용한 완전한 커스텀 덱. 템플릿이나 Codex Grid를 사용하지 않는다.
- 팔레트: Navy `#16263D`, Coral `#F06D5E`, Ivory `#F7F3EA`, Teal `#3D8B83`, Light Teal `#83CDC4`, Ink `#19222E`, White `#FFFFFF`.
- 서체: Noto Sans KR Bold/Medium. 저장소에 고정된 공식 폰트를 사용한다.
- 사진: Pexels API로 받은 존중감 있는 생활 장면. 수동성·동정·과장된 크립토·미래도시 이미지를 사용하지 않는다.
- 구성: 사진 주도 슬라이드와 평면 정보 슬라이드를 교차한다. UI 카드 모음처럼 보이지 않게 하고, 슬라이드마다 한 가지 주장만 둔다.
- 최소 글자 크기: 제목 35pt 이상, 본문 16pt 이상, 표지 제목 50pt 이상.

## 출처와 주장 경계

- 모든 슬라이드 노트에 `[Sources]` 블록을 넣는다.
- 서비스·기술·사업·로드맵 주장은 `docs/whitepaper/IROA_WHITEPAPER_KO.md`의 해당 절을 출처로 적는다.
- 사진은 Pexels 사진 페이지와 사진가를 기록한다.
- 통계 수치를 새로 만들지 않는다. 백서에서 수치가 필요한 경우 백서가 인용한 원출처까지 노트에 적는다.
- 사진 속 인물·장소·제품은 실제 IROA 사용자·시설·제품·제휴사가 아니라는 점을 노트에 기록한다.

## 품질 기준

- 14장 모두 1280×720으로 렌더링하고 개별 원본 크기로 확인한다.
- 제목 줄바꿈, 본문 오버플로, 이미지 왜곡·저해상도·부적절한 크롭이 없어야 한다.
- 자동 오버플로 검사에서 오류가 없어야 한다.
- 공식 워드마크·심볼은 승인된 SVG/PNG만 사용한다.
- 외부 이미지·주장에 대한 출처 노트가 14장 모두 존재해야 한다.
- PPTX는 PowerPoint에서 편집 가능해야 하며, 최종 파일만 `docs/presentations/`에 둔다.
