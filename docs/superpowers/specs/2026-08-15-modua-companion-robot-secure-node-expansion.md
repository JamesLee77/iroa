# MODUA 반려 친구·로봇·보안 노드 확장 설계

- 문서 상태: 사용자 진행 승인 반영
- 작성일: 2026-08-15
- 적용 대상: MODUA 한국어 백서와 공식 DOCX·PDF

## 1. 설계 목표

MODUA를 모바일 앱이나 개인 PC에 종속된 보조 도구가 아니라, 노인과 장애인이 사용하는 기기와 무관하게 생활 과업을 완료하는 접근 가능한 Agent 인프라로 확장한다. 이번 개정은 세 가지를 하나의 서비스 구조로 결합한다.

1. **관계 계층 — 반려 친구:** 독거노인의 고립을 줄이고 일상 대화·루틴·사람 연결을 돕는다.
2. **현실 계층 — 로봇:** 음성·화면·이동·원격 현존을 통해 Agent가 생활공간에서 작동하도록 확장한다.
3. **실행 계층 — MODUA 제공 노드:** 모바일이나 개인 PC가 없어도 장시간·고성능·격리 웹 과업을 처리하고, 검증된 제공자에게 보상한다.

## 2. 검토한 접근과 선택

### 접근 A — 기존 백서에 기능만 추가

반려 대화, 로봇, 보안 노드를 별도 기능으로 덧붙이는 방식이다. 빠르지만 개인 PC 중심 구조와 새 서비스가 충돌하고 개인정보·보상·로드맵이 분리된다.

### 접근 B — 로봇을 별도 사업으로 분리

로봇 사업의 위험을 격리할 수 있지만 MODUA Agent, 키오스크, 워치, 노드의 공통 신원·권한·보상 기반을 중복 구축하게 된다.

### 접근 C — 하나의 신뢰 실행망으로 통합

모바일·워치·키오스크·반려기기·로봇은 사용자 접점, MODUA 보안 노드는 장시간 실행, 기관 노드는 자격 업무를 맡는다. 공통 권한·감사·사람 확인·보상 정책으로 연결한다.

**선택: 접근 C.** 사용자가 요구한 세 확장을 함께 설명하면서도 초기에는 소프트웨어와 고정형 장치부터 검증하고, 물리 로봇의 위험은 단계적으로 제한할 수 있다.

## 3. 제품 구조

### 3.1 반려 친구 Agent

- 사용자가 먼저 선택한 말투·빈도·시간대에 맞춘 일상 대화
- 식사·수분·복약·일정·외출 같은 사용자 설정 루틴 확인
- 가족·이웃·자원봉사자·복지기관과의 연락 및 만남 제안
- 평소와 다른 응답 부재를 감지했을 때 단계적 확인
- 사용자가 지정한 신호·연락처·대응 순서를 언제든 변경·중지·삭제

반려 친구는 고독사를 예측하거나 진단하지 않는다. 성공 기준은 ‘고독사 방지’를 단정하는 것이 아니라 안부 확인 성공률, 사람 연결까지 걸린 시간, 오경보, 사용자 중단권, 외로움·신뢰에 대한 당사자 평가로 둔다.

안부 확인은 `기기 재확인 → 다른 허용 채널 재시도 → 지정된 사람·기관 연결 → 사전 규칙 또는 명백한 긴급 위험에서만 긴급기관 연결` 순으로 수행한다.

### 3.2 로봇 확장

- **1단계:** 고정형 음성·화면·키오스크·원격 현존 장치
- **2단계:** 가정용 이동형 반려 로봇의 대화·알림·원격 가족 연결·제한된 순찰
- **3단계:** 안전표준, 보험, 인간공학, 현장 실증을 통과한 뒤 제한적 신체 보조 검토

로봇은 독립적인 의사결정 권한자가 아니라 MODUA의 신뢰된 접점·노드다. 의료 진단, 기본값 얼굴인식, 강제 감시, 승인되지 않은 녹음, 검증되지 않은 신체 접촉은 금지한다. 가능한 추론은 로컬에서 처리하고, 장시간·고성능 작업은 제한된 실행권한으로 MODUA 보안 노드에 넘긴다.

### 3.3 MODUA 제공 보안 노드

핵심 실행 인프라는 사용자 PC가 아니라 MODUA 또는 승인된 운영자가 제공하는 초기화 가능한 격리 환경이다.

- 모바일·PC가 없는 사용자의 음성전화·워치·키오스크 요청 실행
- 긴 예약 대기, 가격·시간 추적, 취소 자리 확인 같은 장시간 과업
- 다수 사이트 비교, 문서 변환, 로봇 시각·계획처럼 연산량이 큰 과업
- 개인 브라우저와 분리된 Computer Use 세션
- 기관 계약·자격이 필요한 업무를 적격 노드로 라우팅
- 작업 완료 뒤 세션·쿠키·임시 데이터키 삭제와 삭제 증명

개인 PC는 사용자가 이미 로그인한 로컬 자료를 직접 사용해야 할 때만 선택하는 보조 노드로 낮춘다.

## 4. 개인정보·신원·블록체인 경계

### 4.1 신원과 실행권한

- 패스키·기기 인증 또는 기관 확인으로 사용자와 노드의 자격을 검증한다.
- 검증가능한 자격증명(VC)은 필요한 사실만 제시하는 선택적 제출 구조를 우선한다.
- 노드는 원격 증명과 승인된 소프트웨어 상태를 기준으로 과업 등급을 부여받는다.
- 실제 계정 비밀번호·OTP·결제키 대신 목적·도메인·행동·기간이 제한된 일회성 실행권한을 사용한다.

### 4.2 데이터 처리

- 민감정보는 과업별 암호화 작업공간에서만 처리한다.
- 원문을 장기 저장하지 않고 필요한 최소 결과와 사용자용 영수증만 남긴다.
- 사용자·보호자는 접근·중단·철회·삭제·사람 인계를 통제한다.
- 로봇·워치의 연속 신호는 별도 동의 없이 학습이나 보상 산정에 사용하지 않는다.

### 4.3 블록체인 사용 제한

건강정보, 장애정보, 대화·영상·음성 원문, 위치 이력, 실명 신원, 서비스 계정은 블록체인에 기록하지 않는다. 체인은 조건이 충족된 경우 다음 최소 정보의 무결성에만 사용한다.

- 가명화된 노드 자격·상태 증명
- 작업 성공·실패·분쟁 상태의 해시
- 보상 계산 정책 버전과 정산 증명
- 자격 정지·폐기 상태

실제 개인정보와 상세 작업 기록은 분리된 오프체인 저장소에 암호화하고, 체인의 공개성·영구성이 사용자 삭제권을 침해하지 않도록 한다.

## 5. 노드 제공자 보상

보상은 단순 연산량이 아니라 검증된 생활 성과를 기준으로 한다.

`기본 가용성 + 과업 성공 + 접근성 품질 + 사람 인계 품질 + 보안 준수 + 지역 기여 - 실패·지연·보안 위반 패널티`

- 초기 정산은 원화 계약과 비양도성 포인트를 우선한다.
- 조건부 토큰은 서비스·법률·노드 단위경제가 검증된 뒤에만 검토한다.
- 키오스크·복지관·협력기관·전문 운영자는 역할과 책임에 따라 다른 등급을 받는다.
- 개인 데이터의 양, 대화 시간, 과도한 연산 소비를 보상하지 않는다.
- 소수 대형 운영자의 독점과 보상 조작을 막기 위해 지역 다양성·독립 검증·이의제기를 둔다.

## 6. 백서 반영 범위

- 핵심 선언과 대표 하루에 반려 친구·무모바일 실행 시나리오 추가
- 시장 비교에 반려 AI·소셜 로봇·관리형 실행 노드 반영
- 서비스 체계에 관계·안부·사람 연결 Agent 추가
- 모바일을 유일한 통제 중심이 아닌 선택 가능한 개인 접점으로 재정의
- PC 노드 장을 MODUA 보안 실행 노드 장으로 전면 교체
- 워치·키오스크·로봇·기관·보안 노드 전체 아키텍처 재작성
- 개인정보·신원·블록체인·원격 증명 경계 보강
- 보상식, 사업모델, 단계별 로봇 로드맵, 위험·중단 조건 추가
- 정부·W3C·IETF·ISO·원 논문·공식 기술자료를 근거 목록에 추가

## 7. 출판 전 판단 기준

- 반려 친구를 의료·응급 서비스로 과장하지 않았는가
- 로봇의 물리 행동과 감시 위험을 단계적으로 제한했는가
- 모바일이나 개인 PC가 없어도 전체 사용자 여정이 성립하는가
- 블록체인에 개인정보를 저장한다는 오해가 없는가
- 노드 제공자 보상이 데이터 착취나 과도한 연산을 유도하지 않는가
- DOCX·PDF가 동일한 내용이며 모든 페이지가 읽히는가
