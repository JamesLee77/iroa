# MODUA 공개 전 법률·의료·운영 검토 체크리스트

> 검토본 · 2026-08-14 · 대한민국 우선

이 문서는 법률의견서가 아니라 외부 전문가 검토를 빠뜨리지 않기 위한 작업 목록이다. 각 항목은 `검토자 / 검토일 / 근거 문서 / 결론 / 후속 조치 / 공개 가능 여부`를 남긴다. 미해결 항목은 관련 기능의 확정 표현, 출시, 계약, 실증 또는 토큰 발행보다 먼저 닫아야 한다.

## 1. 개인정보보호법과 데이터 책임

- [ ] MODUA, 기관, 병원, 연구자, 외부 사업자의 개인정보처리자·수탁자·공동처리자 역할과 책임을 기능별로 확정한다.
- [ ] 계정, 접근성 설정, 음성·영상, 건강정보, 진료기록, 위치, 결제 상태와 보상 기록별 적법한 처리 근거를 확인한다.
- [ ] 민감정보·고유식별정보의 별도 동의 필요성, 최소수집, 목적 제한과 접근권한을 확인한다.
- [ ] 서비스 운영, 개인화 기억, 에이전트 개선, 의료·임상 연구의 동의와 데이터 흐름이 실제 화면·서버·계약에서 분리되는지 확인한다.
- [ ] 보유기간, 파기, 이용자 열람·정정·삭제·처리정지·동의 철회 절차와 처리기한을 확인한다.
- [ ] 가명정보 결합·재식별 방지, 연구 이용, 제3자 제공과 처리위탁 구분을 확인한다.
- [ ] 클라우드·LLM·분석 도구의 국외이전 여부, 국가·수령자·항목·목적·기간·거부 방법과 보호조치를 확인한다.
- [ ] 침해 탐지, 접근 차단, 영향평가, 법정 신고·통지와 이용자 안내 책임을 정한다.

## 2. 자동화된 결정과 AI 기본법

- [ ] 추천·위험표시·보상보류·지원자 연결이 개인정보보호법상 자동화된 결정에 해당하는지 기능별로 판단한다.
- [ ] 자동화된 결정의 기준과 주요 요소 설명, 거부·이의제기, 사람의 재검토와 결과 정정 절차를 확인한다.
- [ ] 보상 부정 의심이나 모델 판단만으로 필수 서비스·권리·혜택을 제한하지 않는지 확인한다.
- [ ] 인공지능 발전과 신뢰 기반 조성 등에 관한 기본법의 적용 시점과 MODUA의 사업자 지위·의무를 확인한다.
- [ ] 생성형 AI 또는 고영향 AI 해당 여부와 고지, 투명성, 안전성·위험관리, 이용자 보호 의무를 기능별로 확인한다.
- [ ] 외부 LLM 제공자와 MODUA 사이의 로그·학습 이용, 사고 통지, 보안과 책임 배분을 계약에 반영한다.

## 3. 접근 가능한 동의와 대리 절차

- [ ] 목적·항목·이용자·보유기간·철회 방법을 쉬운 한국어, 큰 글자, 음성, 높은 명암과 반복 듣기로 제공한다.
- [ ] 동의와 거부 버튼의 접근성, 선택 대칭성, 단계별 이해 확인과 사본 제공을 당사자 테스트로 검증한다.
- [ ] 전체 동의로 서비스·개인화·개선·연구를 묶지 않고 선택별 거부·철회가 가능한지 확인한다.
- [ ] 장애나 고령만으로 의사결정 능력이 없다고 추정하지 않으며 지원 의사결정 절차를 우선하는지 확인한다.
- [ ] 법정대리·임의대리의 근거, 범위, 기간, 기록, 이해충돌 방지와 철회 절차를 확인한다.
- [ ] 한 사람이 도움 제공, 대리 확인과 최종 승인을 동시에 독점하지 못하게 역할을 분리한다.

## 4. 진료기록 전송과 의료기관 연계

- [ ] 의료법상 진료기록 열람·사본·송부 요건과 사용자 명시적 동의 문구·철회 절차를 확인한다.
- [ ] MODUA와 의료기관의 계약 범위, 개인정보·보안 책임, 장애 대응, 사고 통지와 감사권을 정한다.
- [ ] 화면·PDF 요약과 KR Core V2/FHIR R4 읽기 연계의 출처·측정시각·단위·누락·오류 표시를 확인한다.
- [ ] 병원 연계가 읽기 전용인지, EMR 자동 쓰기·자동 진단·자동 처방을 기술과 계약에서 차단했는지 확인한다.
- [ ] 전송 실패·중복·재시도·철회 시의 상태, 사용자 고지, 기록 정정과 삭제 책임을 정한다.
- [ ] 의료진 포털의 본인확인, 역할별 최소권한, 접근기록, 세션 보안과 퇴직자 권한회수를 확인한다.

## 5. 디지털의료제품·의료기기와 연구심의

- [ ] 웰니스 설명, 건강예측, 모니터링, 경고, 의료진 요약 기능별로 디지털의료제품·의료기기 해당 여부를 식품의약품안전처 기준으로 판단한다.
- [ ] 제품 설명·UI·홍보 문구가 진단, 치료, 예방, 예후 또는 응급판정 효능을 암시하는지 검토한다.
- [ ] 의료기기 또는 디지털의료제품에 해당할 가능성이 있으면 임상·품질·허가·변경관리 의무를 출시 전에 확정한다.
- [ ] 유급 공동설계, 사용성 평가, 가명 평가자료, 웨어러블 건강자료와 병원 실증별 연구 해당 여부와 IRB 심의·면제 필요성을 사전에 판단한다.
- [ ] 연구계획, 모집, 보상, 취약한 연구대상자 보호, 동의, 철회, 이상사건과 결과 공개 절차를 확인한다.
- [ ] 연구 참여 거부·철회가 서비스나 이미 확정된 보상에 불이익을 주지 않는지 실제 흐름으로 검증한다.

## 6. 자원봉사·노무·세무 구분

- [ ] 자원봉사, 공동설계 참여, 일회성 유상 도움, 용역과 근로를 활동별로 구분한다.
- [ ] 지휘·감독, 시간·장소 구속, 반복성, 대가성에 따라 근로자성·최저임금·사회보험·산업안전 의무를 검토한다.
- [ ] 포인트 또는 조건부 토큰 보상이 임금·용역대가·기타소득·사업소득에 해당하는지와 원천징수·신고 책임을 확인한다.
- [ ] 자원봉사자·도움 제공자의 보험, 사고, 신원확인, 교육, 비용정산과 기관 책임을 정한다.
- [ ] 유급 활동을 자원봉사로 표시하거나 임금·용역대가를 양도 불가능한 포인트로 대신하지 않는지 확인한다.

## 7. 금융·가상자산·외국환 경계

- [ ] 원화 접근성 보조가 전자금융거래법상 전자금융업, 전자지급결제대행, 결제대금예치 등에 해당하는지 확인한다.
- [ ] 외부 스테이블코인 흐름에서 매매·교환·이전·보관·중개가 가상자산사업자 업무에 해당하는지 기능별로 판단한다.
- [ ] 제휴 사업자의 FIU 신고 범위, 고객확인·자금세탁방지, 트래블룰과 제재 준수 범위를 공식 자료와 계약으로 확인한다.
- [ ] 해외 발행 자산, 국외 사업자, 환전·송금과 가맹점 원화정산에 외국환거래법상 신고·등록·보고 의무가 있는지 확인한다.
- [ ] MODUA가 이용자 자산·환전재원·개인키를 보관하거나 사실상 통제하지 않는지 기술·운영·회계 흐름으로 확인한다.
- [ ] 워치·모바일·기관 서버의 서명, 인증, 수탁, 전송과 정산 책임 주체를 단계별로 명시한다.

## 8. 수탁·정산·소비자 취소와 환불

- [ ] 신고 사업자, 카드·은행, 가맹점과 MODUA 사이의 수탁·정산·대사·미결제 책임을 계약에 명시한다.
- [ ] 사용자 자금과 회사 자금의 분리, 파산·해킹·오송금·키 상실 시 손실 부담과 보험·준비금 적용 여부를 확인한다.
- [ ] 금액, 수취인, 수수료, 원화 환산, 일회성·정기 여부, 취소·환불 조건을 최종 승인 전에 접근 가능하게 고지한다.
- [ ] 중복 방지 식별자, `확인 중` 상태, 자동 재시도 금지와 원 사업자 상태 대사 절차를 검증한다.
- [ ] 전자상거래·소비자보호상 청약철회, 취소, 환불, 오류정정, 민원과 분쟁조정 책임·기한을 확인한다.
- [ ] 디지털 취약 이용자를 위한 사기·강압 신고, 거래 중지, 신뢰 연락처와 사람 상담 경로를 마련한다.

## 9. 포인트와 조건부 토큰 분류

- [ ] 양도 불가능한 MODUA 포인트가 선불전자지급수단, 전자화폐, 상품권, 가상자산 또는 과세 대상에 해당하는지 사용처·환금성·발행구조로 판단한다.
- [ ] 조건부 토큰이 가상자산, 증권, 투자계약증권, 전자증권, 선불수단 또는 그 밖의 규제 대상인지 발행 전 서면 의견을 받는다.
- [ ] 최대 공급 100억 개와 배분·베스팅이 발행 약속, 모집·판매 권유, 상장·유동성·가격·수익·상환·환매·가치 보장으로 오해되지 않는지 검토한다.
- [ ] 발행 주체, 스마트계약, 지갑·수탁, 판매·배포, 회계·세무, 이용자 보호와 분쟁 책임을 체인 선택 전에 확정한다.
- [ ] 법률·세무·회계, 실제 서비스 수요, 스마트계약 보안감사, 이용자 보호체계가 모두 충족되기 전에는 발행·판매·상장을 진행하지 않는다.
- [ ] 토큰이 없어도 서비스와 양도 불가능한 포인트가 정상 운영되고 필수 서비스 접근이 토큰 보유와 분리되는지 검증한다.

## 10. 표시·광고·후원

- [ ] 의료·건강 기능의 표시가 검증되지 않은 효능, 치료 결과, 응급 대응 또는 의료기관 추천으로 오해되지 않는지 검토한다.
- [ ] 토큰·포인트·후원 홍보가 수익, 가격 상승, 원금·가치, 상장, 환매 또는 유동성을 약속하거나 암시하지 않는지 확인한다.
- [ ] CSR·ESG 후원, 유료 기관 계약, 제휴와 광고를 이용자에게 분명히 구분해 표시한다.
- [ ] 이용후기, 영향 수치, 파트너 로고와 성과 주장을 공개 전에 증빙·사용허락과 함께 검토한다.
- [ ] 노인·장애인을 대상으로 한 부당권유, 다크패턴, 추천인·다단계식 보상이 없는지 확인한다.

## 11. 상표·명칭·공개 자산

- [ ] `MODUA`, `모두아`, 로고와 서비스명에 대해 KIPRIS 지정상품·서비스별 선행 상표 조사를 수행한다.
- [ ] WIPO Global Brand Database와 주요 진출국에서 동일·유사 상표를 전문 검토한다.
- [ ] 도메인, 앱스토어, 소셜 계정, 회사명과 향후 토큰 티커의 충돌·사칭 가능성을 확인한다.
- [ ] 삼성, Samsung Health, Galaxy Watch, Samsung Wallet, 병원·기관 명칭과 로고의 사용허락·상표 가이드 준수를 확인한다.
- [ ] HEFI 명칭·로고·계약·파트너·체인·토큰 경제·NFT·성과·의료 주장을 MODUA가 승계한 것으로 표시하지 않는다.

## 12. 공공조달과 기관 계약

- [ ] 지자체·공공기관 조달 방식, 입찰 참가자격, 직접생산·중소기업·사회적기업 관련 요건을 확인한다.
- [ ] 장애인 접근성, 웹·모바일 접근성, 쉬운 말과 합리적 편의 요구를 제안요청서·검수기준·SLA에 반영한다.
- [ ] 공공 클라우드, 망분리, 보안성 검토, 개인정보 영향평가와 데이터 보관 위치 요구를 기관별로 확인한다.
- [ ] 하도급·재위탁·오픈소스·외부 LLM·SDK 사용 승인과 공급망 보안 책임을 계약에 반영한다.
- [ ] 기관 시스템·병원·신고 사업자 연계의 비용, 일정, 유지보수, 장애, 감사, 종료와 데이터 반환·파기 책임을 정한다.
- [ ] 비식별 집계 보고가 계약 목적을 넘는 성과 과장이나 개인 재식별로 이어지지 않는지 검수한다.
- [ ] 공공계약상 기록 보존, 정보공개, 감사, 민원, 손해배상·보험과 분쟁 관할을 확인한다.

## 13. 최종 공개·출시 게이트

- [ ] 법률·의료·개인정보·노무·금융·토큰·상표·조달 검토의 미해결 항목과 책임자를 한 목록으로 정리했다.
- [ ] 관련 기능별 `진행 / 축소 / 연기 / 제외` 결정을 승인권자가 서명했다.
- [ ] 백서, 서비스 화면, 계약서, 개인정보 처리방침, 동의서와 운영 매뉴얼의 표현이 서로 일치한다.
